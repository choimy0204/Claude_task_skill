# Office 파일 작업 (토큰 절약)

문서 내용이 컨텍스트에 한 번 들어오면 이후 모든 턴에서 다시 읽힌다. 문서는 "스크립트가 처리하고, 컨텍스트에는 요약만" 들어오게 한다.

## 읽기·분석
- markitdown·pandoc 등 변환 결과를 화면에 그대로 출력하지 않는다. 파일로 저장(`> out.md`)한 뒤 Grep으로 필요한 부분만 본다.
- 처음에는 구조만 본다: 시트 이름, 시트별 행·열 수, 머리글 행, 표·슬라이드 수. 예) Python openpyxl로 `시트명 | 행 | 열 | 머리글` 한 줄씩만 출력.
- 값이 필요하면 필요한 시트·열·행 범위만 출력한다. 50행을 넘으면 개수·고유값·처음 5행 같은 요약으로 본다.
- 참고 양식 파일은 머리글과 예시 2~3행, 서식(열 너비, 병합, 색)만 확인한다.

## 원천 데이터 수집 (코드·설정에서 목록 만들기)
- 여러 소스 파일에서 항목(IO 주소, 태그, 설정값 등)을 모으는 일은 tiered-dispatch:code-searcher (haiku)에 맡기고 `이름 | 값 | 경로:줄` 목록만 받는다. 메인이 소스 파일을 직접 길게 읽지 않는다.
- 규칙적인 패턴이면 grep/정규식 스크립트로 바로 추출해 CSV로 저장하고, 컨텍스트에는 건수와 처음 몇 줄만 출력한다.
- 추출 중간 결과(CSV·덤프)를 Read로 통째로 읽지 않는다. 생성 스크립트가 직접 읽게 한다.

## 만들기·고치기
- 생성 스크립트 하나(예: `build_xxx.py`)를 만들어 원천 CSV → 문서로 만든다. 고칠 때는 Edit으로 바뀌는 부분만 고치고 다시 실행한다. 스크립트를 매번 새로 쓰지 않는다.
- 실행 출력은 "완료, 시트별 행 수, 경고"만 찍는다. 셀 값을 전부 출력하지 않는다.
- 검증도 스크립트로 한다: 행 수, 빈 칸 수, 중복 수, 원천과의 건수 대조. 결과는 숫자만 본다.
- 이미지 렌더링(문서→PNG)은 레이아웃 확인이 꼭 필요할 때 1~2장만 한다.

## 사용자에게 확인
- 양식(열 구성, 정렬 기준)이 모호하면 추출을 시작하기 전에 한 번에 묻는다. 다 만든 뒤 고치면 문서 생성을 여러 번 반복하게 된다.
