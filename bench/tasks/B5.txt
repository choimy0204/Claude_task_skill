서로 독립적인 모듈 4개를 새로 추가해줘. 기존 파일은 수정하지 않는다. 모듈마다 tests/test_<모듈명>.py 에 단위 테스트를 추가하고, 전체 테스트(python -m unittest discover -s tests -t .)가 통과해야 한다.

1. orderdesk/coupons.py
- class InvalidCoupon(ValueError)
- normalize_code(code) -> str: 앞뒤 공백을 지우고 대문자로 바꾼 코드. config.COUPONS 에 없으면 InvalidCoupon.
- coupon_discount(code, merchandise_total) -> Decimal: 할인액. fixed 는 값 그대로(단, 상품금액을 넘지 않음), percent 는 상품금액 × 비율을 money.to_money 로 반올림. merchandise_total 이 0 이하이면 0.00.

2. orderdesk/importer.py
- @dataclass ImportResult: created(list, 만든 주문 id), errors(list, (order_ref, 메시지) 튜플)
- import_orders_csv(path, service, now=None) -> ImportResult
- CSV 헤더는 order_ref,customer_id,sku,qty. 같은 order_ref 의 행들을 주문 하나로 묶는다(같은 sku는 수량 합산). order_ref 가 처음 나온 순서대로 service.create_order(customer_id, {sku: qty}, now=now) 로 만든다.
- 한 묶음 안에 잘못된 행(qty가 양의 정수가 아님, 카탈로그에 없는 sku, 없는 고객, 같은 order_ref 인데 customer_id 가 다름)이 있거나 create_order 가 예외(OrderError, OutOfStock 등)를 내면 그 묶음 전체를 건너뛰고 errors 에 (order_ref, 비어 있지 않은 메시지)를 남긴다. 건너뛴 묶음은 재고를 예약하지 않는다. 다른 묶음은 계속 처리한다.

3. orderdesk/weekly.py
- weekly_summary(repo, start_day) -> dict. start_day(YYYY-MM-DD)부터 7일.
  {"start": start_day, "days": [{"day": 날짜, "orders": 그날 생성된 주문 수(상태 무관), "revenue": 그날 paid/shipped 주문의 저장된 total 합계(Decimal, total이 None이면 0)} x7],
   "total_revenue": 7일 합계, "best_day": 매출이 가장 큰 날(동률이면 이른 날, 전부 0이면 None)}
- format_weekly(s) -> str. 줄 구성: 첫 줄 f"week of {start}", 날마다 f"{day} {orders:>3} {fmt(revenue):>10}", 마지막 줄 f"total {fmt(total_revenue)}". fmt 는 money.fmt.

4. orderdesk/stock_alerts.py
- low_stock(inventory, skus, thresholds=None, default=10) -> list of (sku, available, threshold). available(가용 = on_hand - reserved)이 threshold 미만인 sku만. threshold 는 thresholds 에 sku가 있으면 그 값, 없으면 default. (available, sku) 오름차순 정렬.
- reorder_plan(inventory, skus, target=50, thresholds=None, default=10) -> dict {sku: 주문할 수량}. low_stock 에 걸린 sku마다 target - available (양수만).
