# 작업 분배 기본 규칙

## 분배 판단
- 직접 처리: 단일 파일 수정, 짧은 질문, 이미 컨텍스트에 있는 정보로 끝나는 작업
- code-searcher에 위임: 파일 3개 이상을 훑어야 하는 탐색, 호출 위치/사용처 찾기, 긴 로그 분석
- implementer에 위임: 설계가 확정된 구현 작업이 서로 독립적으로 2개 이상일 때
- 설계 판단, 구조 변경 결정, 서브에이전트 결과 검토는 메인이 직접 한다.
- 병렬 진행은 변경 파일이 겹치지 않을 때만 한다. 겹치면 순차로 진행한다.
- 사용자가 "직접 해" 또는 "OO에게 맡겨"라고 지시하면 이 기준보다 그 지시를 우선한다.

## 위임 지시 작성
- 서브에이전트는 이 대화 맥락을 모른다. 위임할 때 목적, 대상 파일/범위, 제약 조건, 완료 기준을 지시에 모두 포함한다.

## 결과 표기
- 서브에이전트를 하나라도 사용했다면, 최종 응답 끝에 아래 표를 붙인다. 메인이 직접 한 작업도 `main` 행으로 포함한다.

  | 담당 | 모델 | 작업 | 변경 파일 | 상태 |
  |---|---|---|---|---|

- 서브에이전트를 사용하지 않았다면 표는 생략한다.

## 커밋
- 커밋할 때는 담당 에이전트 단위로 커밋을 나누고, 커밋 본문에 `Agent: 이름 (모델)`을 적는다.
